Microsoft 365 AitM 악용 피싱 공격으로 계정 탈취 및 급여 관련 이메일 수집

입력: 2026-08-08

요약
- 최근 보고된 피싱 캠페인은 AitM(Adversary-in-the-Middle) 기법을 사용해 Microsoft 365 인증 흐름을 가로채고 계정 탈취를 수행합니다. 공격자는 구글 미트 링크 리디렉션, 캠페인 매니저 추적기, AWS S3에 호스팅된 악성 HTML 등을 연계해 피해자를 피싱 인프라로 유도합니다. 자바스크립트로 브라우저 환경 정보를 수집해 자동화 탐지와 웹드라이버 탐지를 우회하고, PHP 엔드포인트로 수집된 정보를 전송해 프록시된 마이크로소프트 OAuth 인증 엔드포인트로 리디렉션합니다.

- 탈취 후 공격자는 Microsoft Graph API 등을 이용해 테넌트 내부 사용자를 열거하고, 급여·인사·재무 관련 이메일들을 수집합니다. 그러나 공격자는 이메일 발송이나 계정 변조 같은 적극적 변화는 최소화하여 탐지를 회피합니다.

OWASP Top 10 관점에서의 취약점 분석 (OWASP Top 10 2021 기준)

아래 항목들은 이번 공격 시나리오에서 특히 관련성이 높거나 방어 관점에서 주목해야 할 부분입니다.

- A01: Broken Access Control — 공격자는 탈취한 자격증명으로 Microsoft Graph API를 호출하여 테넌트 내 사용자와 메일함에 접근합니다. 권한 검증·최소권한 원칙 미준수 또는 피어 계정 접근 통제가 약할 경우 피해가 확대될 수 있습니다.

- A04: Insecure Design — 피싱 인프라가 공격 목표(재무 담당자 등)를 식별·표적화하고, 자동화된 세션 유지 및 탐지 회피 전략을 통해 설계적으로 방어를 우회합니다. 인증 흐름을 안전하게 설계·강화하지 않으면 OAuth 피싱/리디렉션 공격에 취약합니다.

- A05: Security Misconfiguration — 공격자가 AWS S3와 외부 추적기, 리디렉션 체인을 이용합니다. 잘못된 버킷 설정, 공개 호스팅 허용, 또는 외부 리디렉션 검증 미비는 악성 콘텐츠 호스팅과 전달을 용이하게 합니다.

- A07: Identification and Authentication Failures — 피싱을 통해 자격증명이 유출되거나 세션이 탈취되면 인증 방어가 무력화됩니다. 다단계 인증(MFA) 우회 기법(AitM)과 세션 재사용이 가능한 환경은 인증 실패의 원인이 됩니다.

- A08: Software and Data Integrity Failures — 외부에 호스팅된 HTML/스크립트(예: S3)에 대한 무결성 검증 부재는 공격자가 정상 인프라를 악용하게 합니다. 서명, 콘텐츠 무결성 정책(CSP), 신뢰할 수 있는 출처 검증이 없을 때 위험합니다.

- A09: Security Logging and Monitoring Failures — 공격자는 활동을 제한하고 기존 비즈니스 흐름을 모방해 탐지를 회피했습니다. 충분한 로깅, 이상행위 탐지, 메일박스 액세스 감시가 부재하면 침해를 장기간 식별하지 못합니다.

권고 사항(요약)

- 인증/세션 방어 강화: OAuth 리디렉션 허용 도메인 제한, 인증 시 MFA 강제화, 세션 무결성 검증 및 위험기반 인증 적용.
- 최소권한 원칙과 응용권한 모니터링: Graph API 등 API 접근을 최소 권한으로 제한하고, 비정상적 열람 행위를 탐지하도록 알람 설정.
- 무결성 검증 및 콘텐츠 정책: 외부 호스팅 스크립트에 대한 무결성 검증(서명, SRI)과 CSP 적용으로 악성 스크립트 실행을 제한.
- 보안 구성 점검: 공개 S3 버킷, 리디렉션 검증 미비, 추적기 파라미터 검증 등 구성 요소의 보안 설정 검토.
- 로깅·모니터링 강화: 메일박스 접근 로그, API 호출 로그의 상관분석과 포괄적 엔드포인트 모니터링으로 조기 탐지 체계 구축.
